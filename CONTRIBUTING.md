```markdown
# Contributing Guide

## Workflow

1. Fork the repository
2. Create a feature branch
3. Commit changes
4. Push and create PR

## Branch Naming

- feature/<name>
- fix/<name>
- chore/<name>

## Commit Convention

- feat: new feature
- fix: bug fix
- docs: documentation
- refactor: code improvement

## Code Standards

- TypeScript strict mode
- ESLint + Prettier
- Modular architecture

## PR Requirements

- Must pass build
- Must include description
- Must not break existing APIs
```
